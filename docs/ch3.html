3장. 변환을 잇고, 방향을 세 각도로 적기

동차변환 여러 개를 곱해서 잇는 법과, 변환의 고리에서 모르는 변환 하나를 꺼내는 법을 배운다. 그다음 손끝의 방향을 숫자 몇 개로 적는 네 가지 방법을 비교한다. 세 각도는 편하지만 어떤 자세에서 고장 나고, 네 숫자로 그것을 피한다. 강의 3강(77분)에 해당한다.

3.1 동차변환을 읽는 세 가지 방법

2장에서 만든 동차변환 ATB는 같은 숫자를 세 가지 뜻으로 읽을 수 있다. 3강은 이것을 다시 정리하며 시작한다.

읽는 법 뜻 식
좌표계 기술 (description) {B}가 {A}에서 어느 방향으로, 어디에 있나 ARB와 APB org를 한 행렬에 담는다
매핑 (mapping) 같은 점을 {B}의 숫자에서 {A}의 숫자로 바꾼다 AP = ATB BP
연산자 (operator) 한 좌표계 안에서 점을 돌리고 옮긴다 P₂ = T P₁

세 가지 모두 계산은 행렬 곱 하나다. 문제를 풀 때는 "지금 점이 움직이나, 보는 좌표계가 바뀌나"만 먼저 정한다(2.9절).

이 장은 첫 번째 읽기를 많이 쓴다. 행렬 하나가 "좌표계 하나가 어디에 어느 방향으로 있는지"를 담는다는 읽기다. 좌표계가 여러 개면 그 관계를 행렬 곱으로 적을 수 있다.

강의의 처음 12분은 1991년에 나온 고무 손가락 영상과 그 토론이다. 공기압으로 움직여 가볍고 부딪혀도 안전하지만, 빠르고 정확하게 움직이기는 어렵다. 사람 곁에서 일하는 로봇의 안전은 뒤의 강의에서 다시 나온다.

3.2 변환 잇기: 곱하기만 하면 된다

좌표계가 셋 있다. {A}에서 본 {B}를 알고, {B}에서 본 {C}를 안다. 그러면 {A}에서 본 {C}는 어떻게 구할까?

한 칸씩 건너간다

점 P를 {C}의 숫자로 안다고 하자. 먼저 {B}의 숫자로 바꾸고, 다시 {A}의 숫자로 바꾼다. 2장의 매핑을 두 번 하는 것이다.

P가 어떤 점이든 이 식이 맞는다. 그러니 두 행렬의 곱이 곧 {A}에서 본 {C}다.

가운데 B가 아래와 위에서 만나 지워진다고 보면 외우기 쉽다. 2.8절 끝에서 미리 본 식이다.

수학 더하기: 행렬 × 행렬. 두 행렬을 곱하면, 답의 j번째 열은 "왼쪽 행렬 × 오른쪽 행렬의 j번째 열"이다. 2.5절의 행렬 × 벡터를 열마다 한 번씩 하면 된다. 순서를 바꾸면 답이 대개 달라져서, AB와 BA는 다른 행렬이다.

곱 안에 무엇이 들어 있나

동차변환을 회전 칸과 원점 칸으로 나눠서 곱하면 이렇게 된다.

  • 왼쪽 위: 회전은 회전끼리 곱한다. {C}의 방향은 {B}의 방향에서 한 번 더 돈 것이다.
  • 오른쪽 위: {C}의 원점이다. {B}에서 잰 {C}의 원점을 {A}의 방향으로 돌린 뒤, {B}의 원점을 더한다. 2장의 "돌리고, 더한다"가 그대로 들어 있다.

곱하기만 하면 이 두 가지가 저절로 계산된다. 이것이 동차변환을 쓰는 가장 큰 이유다.

종이 팔로 해 보기

종이 팔에 좌표계 셋을 붙인다.

  • {0}: 받침. 책상에 고정되어 있고 원점은 어깨다.
  • {1}: 링크 1에 붙어 함께 돈다. 원점은 어깨, x₁은 링크 1을 따라간다.
  • {2}: 링크 2에 붙어 함께 돈다. 원점은 팔꿈치, x₂는 링크 2를 따라간다.

이웃한 두 좌표계 사이는 간단하다. {1}은 {0}을 θ₁만큼 돌린 것이다. {2}는 {1}의 x₁ 방향으로 10 cm 간 곳에서 θ₂만큼 돈 것이다.

평면이라 3×3으로 적고, cos θ₁은 c₁, sin(θ₁ + θ₂)는 s₁₂처럼 줄여 쓴다.

두 행렬을 곱하면 {0}에서 본 {2}가 나온다. 왼쪽 위는 θ₁ + θ₂만큼 돈 회전이고, 오른쪽 열 (10c₁, 10s₁)은 팔꿈치의 위치다.

손끝은 {2}에서 (8, 0)인 점이다. 매핑을 한 번 더 하면 받침에서 본 손끝이 나온다.

1장의 손끝 공식이 행렬 곱에서 저절로 나왔다. 4~5강의 순기구학은 관절이 6개일 때 이 일을 4×4로 하는 것이다.

기본값 θ₁ = 30°, θ₂ = 60°에서 0T2의 회전은 90°이고, 팔꿈치는 (8.66, 5)다. 손끝은 (8.66, 13) cm다. 슬라이더로 해 볼 것 세 가지:

  1. θ₂만 바꾼다. 1T2만 바뀌고 0T1은 그대로다. 0T2의 오른쪽 열(팔꿈치)도 그대로다.
  2. θ₁만 바꾼다. 이번에는 1T2가 그대로다. 링크 2는 링크 1에 대해서는 움직이지 않았기 때문이다.
  3. θ₁ = 90°, θ₂ = −90°로 둔다. 0T2의 회전 칸이 단위행렬이 되고, 손끝은 (8, 10) cm다.

잠깐, 생각해 보기. 0T1 1T2 대신 순서를 바꿔 1T2 0T1을 곱하면 무엇이 나올까?

회전 칸은 같다. 평면에서는 θ₁ + θ₂ = θ₂ + θ₁이기 때문이다.

그런데 오른쪽 열이 θ₁과 상관없이 늘 (10, 0)이 된다. 어깨를 돌려도 팔꿈치가 제자리라는 엉뚱한 답이다. 아래 첨자와 위 첨자가 도미노처럼 이어지게(0←1, 1←2) 곱해야 한다.

3.3 변환 고리 풀기

로봇 주위의 좌표계들은 고리처럼 이어진다. 고리 안의 변환 중 하나를 모를 때, 나머지로 그것을 구하는 식을 변환 방정식(transform equation)이라 한다.

상황: 카메라로 본 컵을 팔이 집는다

책상 모서리에 좌표계 {W}를 붙인다. 책상을 위에서 본 평면 문제로 생각한다. 아는 것은 세 가지다.

  1. 받침 {0}은 {W}에서 (30, 10) cm에 90° 돌아가 고정되어 있다. → WT0
  2. 카메라 {C}는 {W}에서 (10, 40) cm에 −90° 돌아가 매달려 있다. → WTC
  3. 카메라가 컵 {G}를 자기 기준 (16, 12) cm에서 봤다. 컵의 방향은 카메라와 같다. → CTG

팔이 알고 싶은 것은 받침에서 본 컵, 0TG다.

같은 방향으로 걷는다

{0}에서 {G}까지 가는 길은 둘이다. 바로 가는 길(모름)과 {W}, {C}를 거치는 길(앎)이다. 두 길은 같은 {G}에 닿으므로 곱도 같다.

첫 칸은 화살표를 거꾸로 걷는다. 아는 것은 WT0(W에서 본 받침)인데, 필요한 것은 0TW(받침에서 본 W)다. 거꾸로 걸을 때는 2.10절의 역변환을 쓴다.

숫자를 넣어 보자. 90° 회전의 역은 −90° 회전이고, 오른쪽 열은 −Rᵀp = −Rᵀ(30, 10) = (−10, 30)이다.

왼쪽부터 차례로 곱한다. 앞의 두 개를 곱하면 받침에서 본 카메라 0TC이고, 거기에 셋째를 곱하면 답이다.

컵은 받침에서 (14, 8) cm에 있고, 받침과 반대 방향(180°)을 본다. 거리가 약 16 cm라 손끝이 닿는 2~18 cm 안이다. 그림에서도 받침의 x₀(위쪽)로 14 cm, y₀(왼쪽)로 8 cm 간 곳에 컵이 있다.

수학 더하기: 곱의 역행렬. (AB)⁻¹ = B⁻¹A⁻¹로 순서가 뒤집힌다. 양말을 신고 신발을 신었다면, 벗을 때는 신발부터 벗는 것과 같다. 변환으로 쓰면 (ATB BTC)⁻¹ = CTB BTA다.

한 바퀴 돌면 단위행렬

고리를 한 바퀴 돌아 제자리로 오면, 아무 데도 안 간 것과 같다. 그래서 고리를 따라 한 방향으로 곱하면 단위행렬 I가 된다.

모르는 것이 하나뿐이면 양쪽에 역행렬을 곱해 꺼낸다. 고리가 다섯, 여섯 칸으로 길어져도 방법은 같다. 늘 한 방향으로 걷고, 화살표가 반대인 칸은 역변환으로 바꾼다.

잠깐, 생각해 보기. 강의의 Romeo는 바퀴로 다니는 받침에 팔을 얹은 로봇이다. 바퀴가 미끄러져서 받침이 어디 있는지 모르는데, 천장의 카메라가 로봇의 손을 본다. 받침의 위치는 어떻게 구할까?

손 {H}가 고리를 이어 준다. 카메라는 CTH를 보고, 받침에서 손까지는 엔코더 각도로 순기구학 0TH를 계산한다.

그러면 CT0 = CTH (0TH)⁻¹이다. 받침이 미끄러져도 손을 보면 받침을 찾는다.

3.4 손끝을 적는 숫자: 위치는 쉽다

여기서부터 강의의 둘째 주제다. 순기구학이 끝나면 받침에서 본 손끝의 동차변환 0TE를 얻는다. 엔코더 값을 넣으면 4×4 행렬의 숫자가 나온다.

그런데 T를 그대로 쓰기는 불편하다. 손끝을 한 곳에서 다른 곳으로 부드럽게 옮기려면 중간값을 만들어야 한다. 속도와 가속도를 말하려면 숫자를 시간으로 미분해야 한다.

그래서 손끝을 서로 얽히지 않은 숫자 몇 개로 적고 싶다. 2.2절의 작업 좌표다.

  • XP(위치)는 T의 넷째 열 위 세 칸에 있다.
  • XR(방향)은 T의 왼쪽 위 3×3, 회전행렬에 들어 있다.

위치를 적는 세 가지 좌표

위치는 쉽다. 숫자 세 개면 되고, 셋은 서로 얽히지 않는다. 적는 방법만 몇 가지 있다.

좌표 숫자 예: 점 (3, 4, 12)
직교 좌표 (Cartesian) x, y, z (3, 4, 12)
원기둥 좌표 (cylindrical) ρ, θ, z (5, 53.1°, 12)
구면 좌표 (spherical) r, θ, φ (13, 53.1°, 22.6°)

ρ는 점을 바닥(xy 면)에 내린 그림자의 길이, θ는 그 그림자를 x축에서 잰 각도다. r은 원점까지의 거리, φ는 z축에서 잰 각도다.

대개는 직교 좌표를 쓴다. 공구를 한 방향으로 쭉 밀어 넣는 일이라면 원기둥 좌표가 편할 수 있다. 각도는 그대로 두고 거리 숫자 하나만 바꾸면 되기 때문이다.

방향은 사정이 다르다. 교수는 "재미는 회전에서 시작된다"고 말한다. 다음 절부터 방향을 적는 방법을 차례로 본다.

3.5 회전행렬을 그대로 쓰면: 숫자 9개, 제약 6개

방향을 적는 첫 방법은 회전행렬의 숫자 9개를 그대로 세로로 세우는 것이다. 회전행렬에는 방향의 모든 정보가 들어 있다. 이것을 방향 코사인 표현(direction cosines)이라 한다(2.6절).

r₁, r₂, r₃는 손끝의 x, y, z축을 받침의 숫자로 적은 세 열이다.

9개 중 자유로운 것은 3개

공중의 물체가 돌 수 있는 방향은 3개다(2.1절). 그런데 숫자는 9개다. 나머지 6개는 제약이 묶고 있다.

  • 길이가 1: |r₁| = |r₂| = |r₃| = 1. 제약 3개.
  • 서로 수직: r₁·r₂ = r₂·r₃ = r₃·r₁ = 0. 제약 3개.

9 − 6 = 3이라서, 숫자 9개가 실제로는 3개의 자유만 가진다. 이처럼 숫자끼리 얽힌 표현을 중복 표현(redundant representation)이라 한다. 2.3절의 여유자유도(redundancy)와는 다른 뜻이다.

잠깐, 생각해 보기. 평면의 2×2 회전행렬은 숫자가 4개다. 제약은 몇 개이고, 자유로운 숫자는 몇 개인가?

두 열의 길이가 1이라는 제약 2개, 두 열이 수직이라는 제약 1개로 모두 3개다. 4 − 3 = 1이다. 평면의 방향은 각도 θ 하나로 정해지니 맞아떨어진다.

왜 문제인가: 중간을 만들 수 없다

손끝을 x = 10 cm에서 22 cm로 옮긴다면 중간값은 쉽다. 13 cm, 16 cm, 19 cm 모두 손끝 위치로 쓸 수 있다. 위치의 세 숫자는 서로 얽히지 않았기 때문이다.

방향은 그렇지 않다. 처음 방향과 끝 방향의 숫자를 칸마다 반씩 섞으면, 그 결과는 대개 회전행렬이 아니다. 아래 그림은 평면에서 회전행렬의 첫 열(x축)만 보여 준다.

  • 숫자를 섞은 축(주황)은 원 안쪽의 곧은 점선을 따라간다. 길이가 1보다 짧아진다.
  • 끝 방향을 180°로 두고 반만 섞으면 길이가 0이 된다. 방향이 아예 사라진다.
  • 각도를 섞은 축(파랑)은 원을 따라가서 길이가 늘 1이다.

그래서 숫자 9개를 그대로 쓰면 움직이는 내내 제약 6개를 지켜봐야 한다. 위치의 숫자는 평평한 판 위를 다니지만, 방향의 숫자는 휘어진 면 위에서만 다니는 셈이다.

3.6 세 각도로 적기: Z-Y-X 오일러 각

자유가 3개라면 숫자도 3개만 쓰고 싶다. 가장 흔한 방법이 각도 세 개다. {A}와 겹쳐 있던 좌표계를 축 하나씩 골라 세 번 돌려서 {B}에 맞춘다.

무엇을 정하나: 축의 순서와 축의 종류

세 번 돌리는 방법은 여러 가지라서, 두 가지를 정해야 한다.

  1. 어느 축으로, 어떤 순서로 돌리나. 예: z → y → x.
  2. 둘째, 셋째에 쓰는 축이 무엇인가. 방금 돌아간 새 축인가, 처음 {A}의 고정된 축인가.

새 축으로 돌리면 오일러 각(Euler angles), 고정된 축으로 돌리면 고정 각(fixed angles)이라 한다. 이 절은 오일러 각을 보고, 고정 각은 3.7절에서 본다.

Z-Y-X 오일러 각: 새 축으로 세 번

강의 예제다. {A}에서 출발해 세 번 돈다.

  1. z축으로 α만큼 돈다. 생긴 좌표계를 {B′}라 한다.
  2. {B′}의 y축으로 β만큼 돈다. 생긴 좌표계는 {B″}다.
  3. {B″}의 x축으로 γ만큼 돈다. 이것이 {B}다.

3.7 고정 각: 순서가 거꾸로 된다

X-Y-Z 고정 각

이번에는 세 번 모두 {A}의 고정된 축으로 돈다. 먼저 xA로 γ, 그다음 yA로 β, 마지막으로 zA로 α만큼 돈다. 비행기와 배에서 쓰는 롤(roll), 피치(pitch), 요(yaw)가 이것이다.

고정된 축으로 도는 것은 2.9절의 연산자다. 물체 위의 점 v를 차례로 돌린다고 생각하자. 세 번 모두 같은 {A}의 숫자로 계산한다.

새 회전이 매번 왼쪽에 붙는다. 그래서 마지막에 돈 z가 맨 왼쪽에 온다.

3.6절의 Z-Y-X 오일러 각과 똑같은 곱이다. 같은 세 각도로, 고정 축으로는 x → y → z 순서로, 새 축으로는 z → y → x 순서로 돌면 같은 자세에 닿는다.

왜 순서가 뒤집히나

두 번만 돌려도 보인다. 아래 그림은 90°씩 두 번 돌린 두 가지 방법이다.

(가)의 둘째 축 "새 y"는 첫 회전(z로 90°)이 옮겨 놓은 y축이다. (나)는 y 회전을 먼저 해 두고, 그다음 처음 z로 물체 전체를 돌린다. 이때 앞서 한 y 회전도 통째로 z로 돌아가서, 결국 "새 y"를 두고 돈 것과 같아진다.

책이나 휴대폰을 들고 직접 해 보면 금방 믿어진다. 책상에 놓고 (가)처럼 한 번, 처음 자세로 돌려 놓고 (나)처럼 한 번 돌려 보자.

3.8 거꾸로: 행렬에서 각도 꺼내기

실제 로봇에서는 방향이 거꾸로 주어진다. 엔코더 각도로 순기구학을 풀면 회전행렬의 숫자 9개가 나온다. 거기서 α, β, γ를 구하는 일을 역문제(inverse problem)라 한다.

짧은 칸부터 본다

3.6절의 행렬에서 짧은 칸 다섯 개만 쓰면 된다.

  • r₃₁ = −sβ
  • r₁₁ = cαcβ, r₂₁ = sαcβ
  • r₃₂ = cβsγ, r₃₃ = cβcγ

r₁₁과 r₂₁을 제곱해 더하면 c²β(c²α + s²α) = c²β다. 그래서 cβ = √(r₁₁² + r₂₁²)이고, sβ는 −r₃₁로 바로 읽는다. sin과 cos을 둘 다 알면 각도가 하나로 정해진다.

수학 더하기: atan2. (0.5, 0.87)과 (−0.5, −0.87)은 방향이 반대인데 y/x가 같아서, tan θ = y/x만으로는 둘을 가를 수 없다. atan2(y, x)는 y와 x를 따로 받아서, 둘의 부호로 사분면까지 가려 −180°~180°의 각도를 준다. 파이썬에서는 np.arctan2(y, x)이고, y를 먼저 쓴다.

이제 세 각도를 차례로 구한다.

제곱근은 양수로 고른다. 그러면 cβ가 양수이고 β는 −90°~90° 사이로 나온다.

예제

(α, β, γ) = (120°, 30°, −45°)로 돌린 행렬이 아래와 같다고 하자. 각도는 모르는 척하고 숫자에서 거꾸로 구해 본다.

  1. β: −r₃₁ = 0.500이다. √(0.433² + 0.750²) = √0.75 = 0.866이다. atan2(0.500, 0.866) = 30°.
  2. α: atan2(0.750/0.866, −0.433/0.866) = atan2(0.866, −0.5) = 120°. tan만 쓰면 tan⁻¹(−1.73) = −60°가 나와서 틀린다.
  3. γ: atan2(−0.612/0.866, 0.612/0.866) = atan2(−0.707, 0.707) = −45°.

α는 둘째 사분면, γ는 넷째 사분면에 있다. atan2가 없으면 둘 다 틀리기 쉽다.

알아 두기. 같은 R을 만드는 각도는 사실 두 벌이다. (α + 180°, 180° − β, γ + 180°)를 넣어도 같은 행렬이 된다. 제곱근을 양수로 고르는 것은 둘 중 β가 −90°~90°인 쪽을 고르는 약속이다.

3.9 표현의 특이점: 짐벌 잠금

3.8절의 식은 cβ로 나눈다. cβ = 0, 곧 β = ±90°이면 나눌 수 없다. 그때는 무슨 일이 생길까?

β = 90°이면 α와 γ가 같은 일을 한다

β = 90°를 3.6절의 행렬에 넣고 삼각함수의 덧셈 공식으로 정리하면 이렇게 된다.

α와 γ가 따로 나오지 않고 차이 α − γ로만 나오니, 행렬에서는 α − γ만 구할 수 있다. α = 50°, γ = 20°와 α = 40°, γ = 10°는 같은 행렬이다. β = −90°이면 반대로 합 α + γ만 구할 수 있다.

그림으로 보면 이유가 분명하다. β = 90°이면 마지막에 도는 축 xB가 바로 아래(−zA)를 본다. α는 zA로 돌고 γ도 같은 줄로 돌아서, 두 각도가 축 하나를 나눠 쓴다.

해 볼 것:

  1. β = 90°에서 α를 움직이고, 다음에 γ를 움직여 본다. 판이 같은 세로축을 중심으로 돈다. 도는 쪽만 반대다.
  2. α와 γ를 같은 양만큼 함께 바꾼다. 예를 들어 (30°, 0°)를 (50°, 20°)로 바꾼다. 행렬이 그대로다.
  3. β를 60°, 30°로 낮춘다. 두 띠가 벌어지고, α와 γ가 서로 다른 움직임을 만든다.

이 현상을 짐벌 잠금(gimbal lock)이라 한다. 짐벌은 고리 세 개를 겹쳐 안쪽 물체를 어느 방향으로나 돌릴 수 있게 한 장치다. 가운데 고리가 90° 서면 바깥 고리와 안쪽 고리가 같은 축으로 돌게 되어, 한 방향으로는 돌릴 수 없게 된다.

로봇이 아니라 적는 방법의 문제다

이것을 표현의 특이점(representation singularity)이라 한다. 로봇은 그 자세에서도 아무 문제 없이 움직인다. 우리가 고른 "세 각도"라는 적는 방법이 그 자세에서 고장 날 뿐이다.

1.4절의 특이점은 다르다. 그것은 팔이 정말로 어떤 방향으로 움직일 수 없는 자세로, 기구학적 특이점이라 하고 7강에서 배운다. 표현의 특이점은 다른 표현으로 바꾸면 사라진다.

그래도 표현의 특이점은 성가시다. 손끝이 그 자세 가까이 가면 α와 γ가 아주 빨리 변한다. 각도의 속도를 구할 수 없어서 부드러운 움직임을 만들기 어렵다.

작게 움직일 때는 특이점을 피해 축 순서를 고를 수 있지만, 크게 돌면 어딘가에서 만난다.

잠깐, 생각해 보기. Z-Y-Z 오일러 각은 어디에서 특이점이 생길까?

β = 0° 또는 180°다. sβ = 0이면 첫 z축과 마지막 z축이 한 줄이 되어, α와 γ가 같은 축으로 돈다. 3.7절의 행렬에서도 r₁₃, r₂₃, r₃₁, r₃₂가 모두 0이 되어 α와 γ를 따로 구할 수 없다.

수학으로 증명된 사실이 하나 있다. 숫자 세 개로 적는 방향 표현은 모두 어딘가에 특이점이 있다. 축 순서를 바꾸면 특이점의 자리만 옮겨 갈 뿐이다.

3.10 네 숫자로: 각-축 표현과 오일러 파라미터

9개는 너무 많고, 3개는 어딘가에서 고장 난다. 그러면 4개를 써 보자.

각-축 표현: 축 하나로 한 번만 돌면 된다

{A}에서 {B}로 가는 회전은 언제나 어떤 축 K 하나로 한 번 도는 것으로 바꿔 말할 수 있다. 길이가 1인 축 K = (kx, ky, kz)와 각도 θ로 적는 이 방법을 각-축 표현(equivalent angle-axis representation)이라 한다.

회전행렬은 아래와 같다. vθ = 1 − cθ다.

K = (1, 0, 0)을 넣으면 RX(θ)가 된다. 거꾸로 R에서 θ와 K를 꺼내는 식은 이렇다.

K에 θ(라디안)를 곱한 (θkx, θky, θkz)는 숫자 세 개로 방향을 적고, 중간값을 만들기도 좋다.

그런데 역시 sin θ로 나누어서, θ = 0° 또는 180°이면 K를 구할 수 없다. 숫자 셋인 표현이라 3.9절의 사실을 피하지 못한다.

오일러 파라미터: 반각으로 만든 네 숫자

축 K와 각도 θ는 그대로 쓰되, 반각 θ/2로 숫자 네 개를 만든다. 이것이 오일러 파라미터(Euler parameters)다. 컴퓨터 그래픽과 드론에서는 단위 쿼터니언(unit quaternion)이라는 이름으로 더 자주 만난다.

네 숫자의 제곱을 더하면 늘 1이다. K의 길이가 1이고, sin² + cos² = 1이기 때문이다.

제약이 하나뿐이라 4 − 1 = 3으로 자유로운 숫자 셋과 맞는다. 제약이 6개인 방향 코사인보다 훨씬 다루기 쉽다. 네 숫자를 4차원 공간의 점으로 보면, 반지름 1인 구면 위의 점이다.

거꾸로: 가장 큰 것으로 나눈다

R에서 ε를 꺼낼 때도 나눗셈이 나온다. 대각선 세 칸의 합이 4ε₄² − 1이므로 ε₄부터 구한다.

ε₄ = 0(θ = 180°)이면 또 0으로 나눈다. 그런데 이번에는 빠져나갈 길이 있다.

제곱 합이 1이므로 넷 중 적어도 하나는 크기가 ½ 이상이다. 넷 모두 ½보다 작으면 제곱 합이 4 × ¼ = 1에 못 미치기 때문이다.

그래서 넷 중 가장 큰 것을 먼저 구하고, 그것으로 나눈다. 예를 들어 ε₁이 가장 크면 이렇게 푼다.

나누는 수가 ½보다 작아지지 않으니 어느 자세에서도 안전하다. ε₂, ε₃가 가장 클 때도 같은 꼴의 식이 있다. 숫자 넷으로 특이점을 없앤 것이다.

해 볼 것:

  1. θ = 60°: ε = (0, 0.3, 0.4, 0.87)이다. 제곱 합은 0.09 + 0.16 + 0.75 = 1이다.
  2. θ = 0°와 180°: 각-축 식은 sin θ = 0으로 나누게 되어 멈춘다. 오일러 파라미터는 가장 큰 칸(ε₄ 또는 ε₃)으로 문제없이 푼다.
  3. θ를 음수로: K가 (0, −0.6, −0.8)로 거꾸로 나온다. −K축으로 거꾸로 도는 것은 같은 회전이다.

잠깐, 생각해 보기. 강의 끝의 퀴즈다. x축으로 60° 돈 회전의 오일러 파라미터와 방향 코사인 표현은?

문제 5와 6의 행렬:

답

답 1. 0T1은 90° 회전이고 원점은 (0, 0)이다. 1T2도 90° 회전이고 원점은 (10, 0)이다. 곱하면 회전은 90° + 90° = 180°이고, 오른쪽 열은 R(90°)(10, 0) + (0, 0) = (0, 10)이다.

손끝은 0T2 (8, 0, 1) = R(180°)(8, 0) + (0, 10) = (−8, 10) cm다. 1장의 공식으로도 10 cos 90° + 8 cos 180° = −8, 10 sin 90° + 8 sin 180° = 10이다. 팔꿈치에서 링크 2가 왼쪽으로 꺾인 자세다.

답 2. 0TH = 0T2 2TH는 회전 180°, 원점 (−8, 10)이다. 고리는 C → H → 0이고, H → 0은 화살표를 거꾸로 걷는다. 그래서 CT0 = CTH (0TH)⁻¹이다.

(0TH)⁻¹은 회전 −180°(= 180°)이고, 원점은 −Rᵀ(−8, 10) = (−8, 10)이다. CTH와 곱하면 회전은 90° + 180° = 270°, 곧 −90°다. 원점은 R(90°)(−8, 10) + (12, 4) = (−10, −8) + (12, 4) = (2, −4)다.

확인: CT0 0TH의 원점은 R(−90°)(−8, 10) + (2, −4) = (10, 8) + (2, −4) = (12, 4)다. 카메라가 본 손과 맞는다.

답 3. 회전행렬이 아니다. M = [[0.5, −0.5, 0], [0.5, 0.5, 0], [0, 0, 1]]이고, 첫 열 (0.5, 0.5, 0)의 길이는 √0.5 ≈ 0.71이라 1이 아니다. 열끼리는 수직이지만 길이 제약이 깨졌다.

그림 3-3에서 끝 방향 90°, s = 0.5로 맞춘 것과 같다.

답 4. RZ(90°) RY(0°) RX(90°) = RZ(90°) RX(90°)이다.

열을 읽으면 xB = yA, yB = zA, zB = xA다. 축 이름이 한 칸씩 돌아갔다. 고정 각으로 읽으면 순서가 뒤집혀, 처음 x축으로 90° 돈 다음 처음 z축으로 90° 도는 것이다(X-Y-Z 고정 각 (90°, 0°, 90°)).

답 5. (α, β, γ) = (−120°, 45°, 135°)다.

  • β = atan2(0.707, √(0.354² + 0.612²)) = atan2(0.707, 0.707) = 45°. cβ = 0.707이다.
  • α = atan2(−0.612/0.707, −0.354/0.707) = atan2(−0.866, −0.5) = −120°. 셋째 사분면이다.
  • γ = atan2(0.500/0.707, −0.500/0.707) = atan2(0.707, −0.707) = 135°. 둘째 사분면이다.

tan만 쓰면 α는 60°, γ는 −45°로 틀린다.

답 6. −r₃₁ = 1, √(r₁₁² + r₂₁²) = 0이므로 β = atan2(1, 0) = 90°인 짐벌 잠금 자세다. sin(α − γ) = 0.5, cos(α − γ) = 0.866이므로 α − γ = 30°만 안다.

예를 들어 (α, γ) = (30°, 0°), (60°, 30°)가 모두 R₆을 만든다. 흔히 α = 0°으로 정하고 γ = −30°로 답한다.

답 7. (1) K = (0, 0, 1), θ/2 = 45°다. ε = (0, 0, sin 45°, cos 45°) = (0, 0, 0.707, 0.707)이고, 제곱 합은 0.5 + 0.5 = 1이다.

(2) ε₄ = ½√(1 − 1 − 1 + 1) = 0이라, ε₄로 나누는 식은 쓸 수 없다. 그래서 가장 큰 칸 ε₃ = ½√(1 − r₁₁ − r₂₂ + r₃₃) = ½√4 = 1부터 구한다. 나머지는 ε₁ = (r₁₃ + r₃₁)/(4ε₃) = 0, ε₂ = (r₂₃ + r₃₂)/(4ε₃) = 0, ε₄ = (r₂₁ − r₁₂)/(4ε₃) = 0이다.

답은 ε = (0, 0, 1, 0)이다. K = (0, 0, 1), θ = 180°에서 바로 구한 (0, 0, sin 90°, cos 90°)와 같다.

파이썬으로 확인

파이썬(numpy)이 있으면 아래를 붙여 넣어 돌려 본다. 주석의 값이 그대로 나온다.

import numpy as np

def rot_x(deg):
    t = np.radians(deg); c, s = np.cos(t), np.sin(t)
    return np.array([[1, 0, 0], [0, c, -s], [0, s, c]])

def rot_y(deg):
    t = np.radians(deg); c, s = np.cos(t), np.sin(t)
    return np.array([[c, 0, s], [0, 1, 0], [-s, 0, c]])

def rot_z(deg):
    t = np.radians(deg); c, s = np.cos(t), np.sin(t)
    return np.array([[c, -s, 0], [s, c, 0], [0, 0, 1]])

def homog2(deg, p):
    """평면 동차변환 3×3: deg만큼 돌고 원점이 p인 좌표계."""
    T = np.eye(3)
    T[:2, :2] = rot_z(deg)[:2, :2]
    T[:2, 2] = p
    return T

def inv_homog(T):
    """동차변환의 역: 왼쪽 위는 전치, 오른쪽 위는 -R^T p."""
    n = T.shape[0] - 1
    R, p = T[:n, :n], T[:n, n]
    Ti = np.eye(n + 1)
    Ti[:n, :n], Ti[:n, n] = R.T, -R.T @ p
    return Ti

def zyx(a, b, g):
    """Z-Y-X 오일러 각 = X-Y-Z 고정 각 (도)."""
    return rot_z(a) @ rot_y(b) @ rot_x(g)

def zyx_angles(R):
    """회전행렬 -> Z-Y-X 오일러 각 (도). cos β > 0인 답."""
    b = np.arctan2(-R[2, 0], np.hypot(R[0, 0], R[1, 0]))
    cb = np.cos(b)
    a = np.arctan2(R[1, 0] / cb, R[0, 0] / cb)
    g = np.arctan2(R[2, 1] / cb, R[2, 2] / cb)
    return np.degrees([a, b, g])

def euler_params(R):
    """회전행렬 -> (ε1, ε2, ε3, ε4). 가장 큰 칸부터 구한다."""
    r = R
    sq = np.array([1 + r[0, 0] - r[1, 1] - r[2, 2],
                   1 - r[0, 0] + r[1, 1] - r[2, 2],
                   1 - r[0, 0] - r[1, 1] + r[2, 2],
                   1 + r[0, 0] + r[1, 1] + r[2, 2]]) / 4
    i = int(np.argmax(sq))            # 가장 큰 칸
    e = np.zeros(4)
    e[i] = np.sqrt(sq[i])
    four = {(0, 1): r[1, 0] + r[0, 1],  # 4 εi εj
            (0, 2): r[2, 0] + r[0, 2],
            (1, 2): r[2, 1] + r[1, 2],
            (0, 3): r[2, 1] - r[1, 2],
            (1, 3): r[0, 2] - r[2, 0],
            (2, 3): r[1, 0] - r[0, 1]}
    for j in range(4):
        if j != i:
            e[j] = four[min(i, j), max(i, j)] / (4 * e[i])
    return e

np.set_printoptions(precision=3, suppress=True)
